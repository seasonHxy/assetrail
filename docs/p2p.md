# 多节点网络与同步

本文描述保留的 **authority 模式：libp2p 交易传播 + 固定出块节点的账本复制**。新的四验证者模式见 [共识网络](consensus.md)。多个节点独立验签和执行，但交易顺序由单个 authority 决定。不是 PBFT、PoS、去中心化验证者网络，也没有自动故障转移。

## 身份与启动

- 钱包使用 secp256k1；网络身份单独使用 Ed25519，由 `settle identity --out <file>` 生成，权限为 0600，已有文件拒绝覆盖。
- `settle peer-id --key <file>` 读取已有网络身份对应的 Peer ID。
- 未设置 `--validators` 时，指定 `--p2p-key` 后必须提供 `--authority <peerId>`。自己就是 authority 时出块，否则为 follower，`Node.Produce` 也会阻止 follower 出块。
- `--peers` 为逗号分隔的 `/ip4/.../tcp/.../p2p/<id>` multiaddress。follower 必须包含 authority 的直连地址。可附加其他 follower，最多配置 32 个地址。
- `--p2p-listen` 默认 `/ip4/127.0.0.1/tcp/0`。端口 0 会分配随机端口，可从启动日志或 `chain_getPeers` 读取实际地址。需要让其他节点按静态配置重连时，应使用固定端口。
- `--p2p-interval` 默认 200ms，控制周期传播和同步。新交易入池或区块提交会唤醒交换循环，事件合并等待 50ms，周期同步继续负责重传和重连。`--block-time` 默认 100ms，最小 50ms，只对 authority / 单节点生产者有作用；它是检查间隔，协议整秒时间戳不变，最多每秒一块。

libp2p TCP 连接使用其默认认证安全通道与流多路复用，Peer ID 由远端网络密钥验证。本版本显式关闭 Relay，仅启用 TCP，不实现 DHT、mDNS、GossipSub、NAT 打洞或公网发现。交易传播使用自定义流协议的周期扇出与重传。

## 数据目录约束

每个节点独占自己的数据目录。`network.json` 将目录绑定到本节点 Peer ID 和 authority，写入时持有目录锁，使用临时文件、fsync 和原子替换。

重启时不允许换身份、换 authority，或将网络目录作为 solo 打开。已有非空 solo 历史也不能直接转换成 P2P 历史；用新目录从共同创世配置开始。钱包文件、网络身份、区块数据分别存储，不能共用一个文件。

## 交易传播

各节点定期向 bootstrap 和当前连接的其他节点交换 Mempool 页面：

1. 按 sender、nonce 排序，每次最多 32 笔，轮换偏移。
2. 接收方执行现有签名、Chain ID、nonce 窗口、容量和替换价格检查。
3. 重复、过期或无效交易不会再次执行；正常重复入池错误在传播中忽略。
4. 接收的有效交易进入本地 Mempool，并参与后续扇出。

库存交换会重复发送未确认交易，用来修复断线或初次连接时遗漏的传播。没有永久的“见过即丢弃”集合，因此落后节点追上状态后仍可重新接收之前 nonce 超窗的交易。Mempool 本身仍未持久化：只有存活节点保留的待确认交易能够在出块节点恢复后重新传播；所有节点同时重启会丢失未确认交易。

## 区块同步

协议为 `/settlelab/exchange/1.0.0`，每个认证 stream 一个请求和一个响应。请求和响应都绑定创世块哈希及 authority；任意一项不同即拒绝。

follower 只从配置的 authority 的认证连接导入区块，不依据消息中自报的身份授权。普通 follower 可以参与交易中继，但不能决定另一节点导入哪份历史。

每次同步携带当前本地高度，响应最多包含已知祖先块和 4 个后续区块：

1. 验证远端高度不落后于本地、已知祖先哈希与本地 tip 一致。
2. 检查批次大小、连续高度和批次末端与声明 tip 的一致性。
3. 对每个新区块验签、重执行、检查 TxRoot / StateRoot，并持久化后提交。
4. 清理已消费 nonce、重建本地回执索引，下轮继续拉取后续批次。

这是逐块提交，而不是整批事务；后续坏块不撤销已独立校验并持久化的前缀。无效远端区块不会把节点标记为磁盘故障。已有冲突历史拒绝覆盖，不提供重组或最长链选择。

如果 authority 比本地已确认高度低，或返回不同历史，节点保留本地账本并在 peer 的 `lastError` 暴露问题。authority 停机后 follower 仍可接受交易入池，但不自行出块；authority 恢复原身份、地址和数据后，周期交换继续处理积压。

## 边界与验证

- 帧为 4 字节大端长度加 JSON，单帧上限 4 MiB，限制在分配正文内存之前检查。
- 每次库存最多 32 笔，每次同步最多 4 个新区块，入站处理并发最多 8，单 stream 设有 5s 截止时间。
- 对等连接使用 libp2p connection manager；每轮最多联系 32 个 peer。不可达 peer 独立超时，不阻塞本地出块。
- `chain_getPeers` 显示 Peer ID、地址、连接状态、最近成功和错误。连接成功不等于已经同步；用高度和状态根判断账本进度。`/healthz` 表示节点本身可用，不表示与 authority 连通。
- 本版本没有成员准入、完整抗拒绝服务策略或惩罚机制，仍是本地开发网络。
- authority 被信任提供唯一顺序；它若签出/发送不同有效历史，当前实现不能提供拜占庭安全或对外可验证的区块证书。传输认证也不等于区块携带了可转交验证的共识签名。

`make check` 包含真实 libp2p 主机、分批追块、错创世握手拒绝、冲突历史和错误响应测试。`make smoke-network` 启动四个独立进程，验证转账从 follower 到 authority 再同步全网，以及 follower 和 authority 分别停机重启的行为。

当前 libp2p 固定为 v0.32.2，匹配已验证的 Go 1.21.1 工具链；升级 Go / libp2p 应一起运行上述测试。依赖接口参考 [go-libp2p 官方仓库](https://github.com/libp2p/go-libp2p/tree/v0.32.2)。
